# Socratic Tutor State Machine Implementation Spec

> **Date:** 2026-05-05
> **Status:** Approved
> **Version:** 1.0

## 1. Overview

**Goal:** Implement a constrained Socratic Tutor Agent using a state machine that guides students through learning without giving direct answers. The Tutor is NOT a free ReAct agent - it operates under strict pedagogical constraints.

**Core principle:** Every output must be (a) Socratic, (b) anchored to KG triples, (c) prompt injection resistant.

---

## 2. State Machine

### 2.1 States

| State | Trigger | Tutor Behavior | Exit Condition |
|-------|---------|----------------|----------------|
| `diagnose` | `p_know < 0.5` for target concept | Ask probing questions to identify misconception | Misconception identified → `hint_ladder` |
| `hint_ladder` | Misconception identified | Give hints L1 → L2 → L3 progressively | Student responds correctly → `counter_example`; Still wrong after L3 → `guide` |
| `guide` | Hint ladder exhausted OR student asks for help | Guide student through reasoning step by step | Student makes progress → `counter_example`; 3 attempts → `escalate` |
| `counter_example` | Student gives answer close to correct | Provide counter-example to test understanding | Understanding confirmed → `consolidate`; Still gaps → back to `guide` |
| `consolidate` | `p_know > 0.8` | Summarize KG path + recommend practice problems | Session ends |
| `escalate` | 3+ turns in same state without progress | Offer explanation mode or human expert | Student accepts explanation → provide; else → queue for expert |

### 2.2 State Transitions

```
diagnose ──→ hint_ladder (misconception found)
hint_ladder ──→ guide (L3 exhausted)
hint_ladder ──→ counter_example (answer near correct)
guide ──→ counter_example (progress made)
guide ──→ escalate (3 attempts failed)
counter_example ──→ consolidate (understanding confirmed)
counter_example ──→ guide (gaps remain)
consolidate ──→ [END]
escalate ──→ [END or queue expert]
```

### 2.3 State Data Model

```python
class TutorState(Enum):
    DIAGNOSE = "diagnose"
    HINT_LADDER = "hint_ladder"
    GUIDE = "guide"
    COUNTER_EXAMPLE = "counter_example"
    CONSOLIDATE = "consolidate"
    ESCALATE = "escalate"


class TutorSession(Base):
    __tablename__ = "tutor_sessions"

    id = Column(Integer, primary_key=True)
    user_id = Column(Integer, nullable=False, index=True)
    concept_id = Column(String, nullable=False)
    current_state = Column(String, nullable=False)
    turns_in_state = Column(Integer, default=0)
    target_concept_id = Column(String, nullable=False)
    misconception = Column(String, nullable=True)
    hint_level = Column(Integer, default=0)  # 0-3
    created_at = Column(DateTime(timezone=True), server_default=func.now())
    updated_at = Column(DateTime(timezone=True), server_default=func.now(), onupdate=func.now())


class TutorMessage(Base):
    __tablename__ = "tutor_messages"

    id = Column(Integer, primary_key=True)
    session_id = Column(Integer, ForeignKey("tutor_sessions.id"))
    role = Column(String, nullable=False)  # "tutor" | "student"
    content = Column(Text, nullable=False)
    hint_level = Column(Integer, nullable=True)
    state_at_time = Column(String, nullable=False)
    created_at = Column(DateTime(timezone=True), server_default=func.now())


class TutorHintTemplate(Base):
    __tablename__ = "tutor_hint_templates"

    id = Column(Integer, primary_key=True)
    concept_id = Column(String, nullable=False, index=True)
    hint_level = Column(Integer, nullable=False)  # 1, 2, 3
    template_text = Column(Text, nullable=False)
    # Variables: {concept}, {prerequisite}, {example}
```

## 3. Hint Generation (Hybrid)

### 3.1 Level Definitions

| Level | Type | Description | Example |
|-------|------|-------------|---------|
| **L1** | Template | Direction hint - points toward thinking direction | "Think about what {concept} relates to in the KG" |
| **L2** | Template + LLM | Key concept hint - names the prerequisite | "Remember that {concept} requires understanding {prerequisite}" |
| **L3** | LLM Generated | Step hint - half a derivation | "If you have X, then Y follows because..." |

### 3.2 Template Storage

```python
# Pre-defined templates for common patterns
HINT_TEMPLATES_L1 = [
    "想想这个概念和哪个前置概念有关？",
    "有没有考虑过从定义出发？",
    "试着画个图来理解",
]

HINT_TEMPLATES_L2 = [
    "记住 {concept} 需要先理解 {prerequisite}",
    "这个问题的关键在于 {key_concept}",
]

HINT_TEMPLATES_L3 = []  # L3 always generated by LLM
```

### 3.3 LLM Hint Generation

For L3 hints and complex concepts:
1. Query KG for `concept` and its `requires` relationships
2. Build context: `{prerequisites} → {concept} → {applications}`
3. Generate hint that guides student to next step without giving answer

## 4. Response Generation

### 4.1 Tutor Response Structure

```python
class TutorResponse:
    message: str                    # The tutor's message
    state: TutorState               # Current state after this turn
    hint_level: Optional[int]      # 0-3 if hint was given
    kg_citations: List[dict]       # [{concept_id, triple_id, chapter_ref}]
    suggestions: List[str]         # Suggested next actions
    is_final: bool                  # True if session should end
```

### 4.2 KG Citation Requirement

Every tutor message MUST include citations to KG nodes:
```json
{
  "message": "Remember that slope requires understanding of ratio.",
  "kg_citations": [
    {"concept_id": "slope", "relation": "requires", "target_id": "ratio", "confidence": 0.9}
  ]
}
```

## 5. Prompt Injection Defense

### 5.1 Detection Rules

- Block patterns: "ignore previous instructions", "system prompt", "you are now"
- Rate limit: Max 3 consecutive student messages without tutor response
- Input sanitization: Strip markdown code blocks from student input

### 5.2 Defense Response

If injection detected, respond with:
```
"I notice something unusual in your message. Let's stay focused on learning {concept}. Can you tell me what you find challenging about this?"
```

## 6. API Endpoints

### 6.1 Start Session

**POST** `/api/v1/tutor/sessions`

Request:
```json
{
  "user_id": 123,
  "concept_id": "slope_in_linear_equations"
}
```

Response:
```json
{
  "session_id": 456,
  "state": "diagnose",
  "message": "Let's explore the concept of slope. What does slope represent in your understanding?",
  "kg_citations": []
}
```

### 6.2 Send Message

**POST** `/api/v1/tutor/sessions/{session_id}/messages`

Request:
```json
{
  "content": "I think slope is how steep a line is",
  "role": "student"
}
```

Response:
```json
{
  "session_id": 456,
  "state": "hint_ladder",
  "message": "That's a good start! Slope does relate to steepness. But what determines HOW we measure that steepness?",
  "hint_level": 1,
  "kg_citations": [{"concept_id": "slope", "relation": "describes", "target_id": "line_steepness"}],
  "suggestions": ["Think about units", "Consider the formula"]
}
```

### 6.3 Get Session State

**GET** `/api/v1/tutor/sessions/{session_id}`

Response:
```json
{
  "session_id": 456,
  "user_id": 123,
  "concept_id": "slope_in_linear_equations",
  "current_state": "hint_ladder",
  "turns_in_state": 1,
  "hint_level": 1,
  "misconception": "confuses_steepness_with_measurement"
}
```

## 8. Integration with BKT

The tutor uses mastery data from BKT:

1. **On session start:** Query `MasteryRecord` for `concept_id` to get `p_know`
2. **If `p_know >= 0.5`:** Skip `diagnose`, go directly to appropriate state based on recent performance
3. **On session end:** If mastery improved, update BKT via `PUT /mastery/update`
